# DET-012 — PowerShell Execution Telemetry and Investigation

## Objective

Validate the PowerShell execution telemetry path on DC-01 and determine how the existing custom PowerShell detection family behaves against a controlled benign PowerShell → PowerShell execution.

The validation covers:

`PowerShell execution → Sysmon Event 1 → Wazuh ingestion → detection → ProcessGuid investigation → Sysmon Event 11`

The exercise also records an observed false-positive/tuning candidate in native Wazuh rule 92213.

## Scope

- Host: `DC-01`
- Domain: `corp.home.arpa`
- User: `CORP\admin`
- Telemetry: Sysmon + Wazuh
- Test type: controlled benign PowerShell execution
- Validation date: 2026-09-23

## Controlled Test

The following command was executed on DC-01:

```powershell
powershell.exe -NoProfile -Command "Write-Output 'DET012-PowerShell-Test'"
```

The command completed successfully and produced the expected marker.

The parent process was PowerShell rather than CMD.

## Wazuh Detection

The Sysmon Event ID 1 was ingested into Wazuh.

The observed Wazuh detection was:

- Rule: **92027**
- Level: **4**
- Description: **Powershell process spawned powershell instance**
- MITRE ATT&CK: **T1059.001 — PowerShell**

This confirms that the observed native Wazuh detection specifically identified the PowerShell → PowerShell parent/child relationship.

## Existing Custom PowerShell Rules

The lab already contains the custom PowerShell detection family in:

`/var/ossec/etc/rules/local_rules.xml`

| Rule | Detection |
|---|---|
| **100101** | PowerShell encoded command using `-EncodedCommand` / `-enc` |
| **100102** | `cmd.exe → powershell.exe` |
| **100103** | `cmd.exe → powershell.exe` with encoded command |

The DET-012 command did not contain an encoded command and its parent process was PowerShell rather than CMD.

A search of `/var/ossec/logs/alerts/alerts.json` for rules 100101–100103 produced no matching alerts during this validation.

Therefore the existing custom PowerShell rules remained silent for this benign PowerShell → PowerShell execution.

## ProcessGuid Investigation

The Sysmon ProcessGuid was used as the primary investigation pivot:

`{939ab59d-7551-6ab3-7002-000000001500}`

The pivot returned both the Process Create event and a related Sysmon Event ID 11.

This demonstrates a practical SOC investigation method: pivoting from a process alert into related telemetry generated by the same process.

## Native Rule 92213

The Event ID 11 activity generated Wazuh rule **92213**.

The installed native rule was inspected at:

`/var/ossec/ruleset/rules/0830-sysmon_id_11.xml`

The rule matches Sysmon Event ID 11 when the target filename is under a user `AppData\Local\Temp` path and has one of several executable/script extensions, including `.ps1`.

Observed behavior:

- Rule level: **15**
- Description: **Executable file dropped in folder commonly used by malware**
- MITRE ATT&CK mapping: **T1105**

The controlled benign PowerShell execution triggered this rule because PowerShell created the temporary `.ps1` policy-test file.

## Detection Engineering Finding

The DET-012 result demonstrates an important distinction:

**Telemetry or a rule match does not by itself establish malicious activity.**

The benign test produced a high-level native 92213 alert because its filename/path pattern matched the rule.

The observed behavior is therefore a **tuning/false-positive candidate**, not evidence that the test was malicious.

The native rule was not modified during this exercise.

## Detection Coverage Boundary

DET-012 also demonstrates a coverage boundary in the existing custom PowerShell detection family.

Current custom coverage:

- Encoded PowerShell → 100101
- CMD → PowerShell → 100102
- CMD → encoded PowerShell → 100103
- PowerShell → PowerShell → not matched by 100101–100103

This is recorded as an observed coverage boundary, not as justification for immediately creating another rule.

A future custom rule should only be designed after defining a specific behavior worth detecting and identifying reliable telemetry fields.

## ATT&CK Context

The native Wazuh detection mapped the PowerShell process activity to:

- **T1059.001 — PowerShell**

The native Rule 92213 mapping observed during the same benign execution was:

- **T1105 — Ingress Tool Transfer**

The ATT&CK mappings are retained as observed from the installed Wazuh rules; the benign nature of the controlled test means the mappings should not be interpreted as proof that the activity represented an attack.
