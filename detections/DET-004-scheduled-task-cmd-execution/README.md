# DET-004 — Scheduled Task Created with CMD Execution

## Objective

Detect creation of a Windows scheduled task whose task definition executes `cmd.exe`, using Windows Security Event ID 4698 and Wazuh contextual detection.

## Lab Environment

- Endpoint: WIN-01
- Endpoint IP: 10.10.20.100
- SIEM/Manager: WAZUH-01
- Windows Event ID: 4698 — A scheduled task was created
- Built-in Wazuh rule: 60228
- Custom Wazuh rule: 100105
- MITRE ATT&CK: T1053.005 — Scheduled Task/Job: Scheduled Task
- MITRE ATT&CK: T1059.003 — Command and Scripting Interpreter: Windows Command Shell

## Telemetry Prerequisite

Before testing, Windows auditing for **Other Object Access Events** was verified as disabled:

`No Auditing`

The setting was enabled on WIN-01 with:

```powershell
auditpol /set /subcategory:"Other Object Access Events" /success:enable /failure:enable
```

Verification returned:

```text
Other Object Access Events    Success and Failure
```

This enabled Windows Security Event ID 4698 generation for the controlled test.

## Controlled Positive Test

A temporary scheduled task named `DET004-TestTask` was created on WIN-01:

```cmd
schtasks /create /tn "DET004-TestTask" /tr "cmd.exe /c echo DET004-Test" /sc once /st 23:59 /f
```

Windows generated Event ID 4698.

The Wazuh event contained:

- Event ID: `4698`
- Task name: `\\DET004-TestTask`
- Subject user: `Administrator`
- Subject domain: `CORP`
- Computer: `DESKTOP-8PB40LJ.corp.home.arpa`
- Task XML field: `data.win.eventdata.taskContent`

The task XML showed:

```xml
<Command>cmd.exe</Command>
<Arguments>/c echo DET004-Test</Arguments>
```

## Native Wazuh Detection

Wazuh's built-in rule **60228** already detected the raw Event 4698:

> A scheduled task was created

The native rule mapped the event to MITRE T1053.

The custom detection therefore adds contextual value instead of duplicating the native 4698 detection.

## Custom Wazuh Detection

Custom rule:

```xml
<rule id="100105" level="12">
  <if_sid>60228</if_sid>
  <field name="win.eventdata.taskContent" type="pcre2">(?i)&lt;Command&gt;\s*cmd\.exe\s*&lt;/Command&gt;</field>
  <description>Scheduled task created with cmd.exe execution.</description>
  <mitre>
    <id>T1053.005</id>
    <id>T1059.003</id>
  </mitre>
  <group>scheduled_task,windows_command_shell,persistence,execution,</group>
</rule>
```

The rule syntax was validated with:

```bash
sudo /var/ossec/bin/wazuh-analysisd -t
```

The test completed without syntax errors.

## Positive Validation

After the manager was restarted, the scheduled task was recreated.

Wazuh Threat Hunting showed:

- Rule ID: `100105`
- Level: `12`
- Description: `Scheduled task created with cmd.exe execution.`
- MITRE: `T1053.005`, `T1059.003`
- Agent: WIN-01

The custom detection fired successfully.

## Negative Validation

A second temporary scheduled task was created using PowerShell rather than CMD:

```cmd
schtasks /create /tn "DET004-FP-Test" /tr "powershell.exe -NoProfile -Command echo DET004-FP" /sc once /st 23:59 /f
```

The Wazuh search for rule `100105` showed only the earlier positive result.

No new `100105` alert was observed for the PowerShell task.

The native scheduled-task rule may still detect the underlying Event 4698; this is expected.

## IOC / IOA / TTP

### IOC

No malicious IOC was established. The executable and command were deliberately benign lab test content.

### IOA

Creation of a scheduled task configured to execute `cmd.exe`.

### TTP

- T1053.005 — Scheduled Task/Job: Scheduled Task
- T1059.003 — Command and Scripting Interpreter: Windows Command Shell
- Primary tactics represented by the mapped techniques include Persistence and Execution.

## Investigation Assessment

The activity was intentionally generated as a controlled detection-engineering test.

The alert is therefore a security-relevant signal, not proof of malicious activity.

Useful investigation context includes:

- Who created the task.
- Task name and URI.
- Scheduled trigger.
- Command and arguments.
- Run-as identity and logon type.
- Run level.
- Whether the task is hidden.
- Parent process or process-creation telemetry around task creation.
- Subsequent execution of the task.
- Network activity generated by the task.

## False Positives

Potential legitimate activity includes:

- Software installation and update mechanisms.
- Enterprise management agents.
- Administrative scripts.
- Scheduled maintenance jobs.
- IT automation using CMD.

The detection should therefore be investigated with user, task, command-line, host, and surrounding process context.

## Detection Limitation

The current rule identifies scheduled-task creation where the task XML contains a `cmd.exe` command.

It does not determine whether the command is malicious.

It also does not cover scheduled tasks that execute PowerShell, scripts, LOLBins, or other binaries without `cmd.exe`.

Future improvements can correlate:

1. Task creation with subsequent task execution.
2. Task creator with administrative privilege.
3. Task action with suspicious command-line patterns.
4. Task creation with process creation telemetry.
5. Task creation with network activity.
6. Task persistence across reboot or logon.

## Cleanup

Both temporary test tasks were removed after validation:

```cmd
schtasks /delete /tn "DET004-TestTask" /f
schtasks /delete /tn "DET004-FP-Test" /f
```

Subsequent queries confirmed that both tasks no longer existed.

## Validation Result

**PASS — Event 4698 was generated and ingested by Wazuh; native rule 60228 detected the event; custom rule 100105 fired for CMD-based scheduled-task creation; the negative PowerShell test did not trigger 100105; test artifacts were removed.**
